## Install (first time)

```powershell
powershell -ExecutionPolicy Bypass -File C:\llm-platform\scripts\platform-setup.ps1     # secrets, C:\AIWorkspace, .env
powershell -ExecutionPolicy Bypass -File C:\llm-platform\scripts\platform-up.ps1 -Build # build + start everything
```

Then:
1. Open `http://127.0.0.1:8090/admin` and sign in as `admin` with the password in `platform\secrets\admin_bootstrap.txt`. You're asked to choose your own password right away.
2. Open `http://127.0.0.1:8090` for the chat. It works while you're signed in. Alternatively, create a `chat` token under Account and paste it into the web UI under Settings → API key.

Prerequisites already on this laptop:
- Docker Desktop 29.7, set to start at login
- Ollama 0.34.2 (per-user), with the model imported by `ollama create qwen3.6-35b-a3b -f platform\ollama\Modelfile.qwen3.6-35b-a3b`. User env vars `OLLAMA_VULKAN=1` and `OLLAMA_IGPU_ENABLE=1` let it use the Iris Xe through Vulkan
- `C:\llm\models\Qwen3-Embedding-0.6B-Q8_0.gguf`, SHA-256 `06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439`

## Everyday

| Task | Command |
|---|---|
| Start / apply folder changes | `scripts\platform-up.ps1` (`-Build` after code changes, `-Search` for SearXNG) |
| Stop (data kept) | `scripts\platform-down.ps1` |
| Backup now | `scripts\platform-backup.ps1` |
| Restore (verify only) / swap | `scripts\platform-restore.ps1 -File platform\backups\<dump>` then add `-Swap` |
| Checks (lint, types, tests, audit) | `scripts\platform-check.ps1` (`-Only tests`, `-Pytest "-k memory"`) |
| Benchmarks | `scripts\platform-bench.ps1` → `platform\bench\results\` |
| Live end-to-end with the real model | `cd platform; docker compose exec -T backend python - < bench/e2e_live.py` |
| Logs | `docker compose logs -f backend` (JSON, with `request_id` and `correlation_id`) |
| DB shell | `docker compose exec postgres psql -U postgres -d aiplatform` (the password is in `secrets\pg_superuser.txt`) |
| Switch model runtime | Admin → Model → Provider (Ollama or llama.cpp). **Stop the other runtime first**: 40 GB RAM fits one 22 GB model |

Only one model fits in memory:
- To use llama.cpp: quit Ollama from its tray icon, run `C:\llm\scripts\start.ps1`, and set the provider to `openai_compat`.
- To use Ollama: run `C:\llm\scripts\stop.ps1`.

## Tests

`platform-check.ps1` builds the `dev` image and runs:
- `ruff check`
- `mypy --strict` over `src`
- `pytest` against a throwaway `pgvector` Postgres on an internal network, with random per-run passwords. The gate requires ≥1 test, 0 failures, 0 errors and **0 skipped**
- `pip-audit` and `bandit`
- gitleaks, if installed

| Suite | Covers |
|---|---|
| `tests/unit` | permission engine, context builder, RRF fusion, tsquery sanitising, sensitivity and classifier |
| `tests/security` | path-traversal corpus + hypothesis property test, symlink escapes, SSRF (URL forms, IP classes, DNS rebinding via a patched resolver, redirects to metadata, size and content type), shell injection, filesystem tool safety (backups, trash, read-only roots, executable extensions, dry run) |
| `tests/db` | background jobs (extraction, confidence gating, pre-emption), least-privilege grants, append-only hash-chained audit, SQL-injection strings, memory lifecycle (dedupe, supersede, secrets, personal data, poisoning candidates, expiry, delete), hybrid and keyword retrieval, short-term TTL |
| `tests/api` | auth (no token, bad token, scopes, CSRF, elevation, login throttle), Host/Origin checks, admin XSS escaping, remember→recall across chats, history trimming to the budget, tool round trip, approval flow (approve and expire), indirect prompt injection, taint escalation, unknown/policy tools, traversal and SSRF through the model, SSE format, health and metrics |

The LLM is replaced by a scripted `FakeProvider` and the embedder by a deterministic `FakeEmbedder`, so the 235 tests are fast (~30 s) and reproducible. `bench/e2e_live.py` covers the real model.

## Code conventions

- Python 3.13, `ruff format` (130 columns), `ruff check`, `mypy --strict`. There are no module-level singletons: everything is wired in `main.AppContainer`.
- Domain code doesn't import FastAPI. Only repositories and adapters use asyncpg and httpx.
- New SQL goes in a new `db/migrations/NNNN_*.sql` file. Never edit an applied migration.
- New tools follow `docs/TOOLS.md` §8. Anything a tool reads from outside must set `untrusted_source`.
- PowerShell scripts follow the repo's dense one-line style and target Windows PowerShell 5.1.

## Rotating secrets

1. Stop the stack with `platform-down.ps1`.
2. For a database role: `docker compose up -d postgres`, then `ALTER ROLE aimem_app PASSWORD '<new>'` in psql, and write the same value to `secrets\pg_app.txt`.
3. `session_key`: replace the file. This signs everyone out.
4. `admin_bootstrap` is only used when no users exist.
5. Start again with `platform-up.ps1`.
